# Public marketing architecture
- General-tree service pages use the shared service data and ServicePage renderer so runtime copy, initial HTML and service schema stay aligned.
- Public navigation groups and quote choices are derived from service data while retaining legacy option labels so existing intake values remain compatible.
- Keep all public routes in the shared SEO route table because it drives initial metadata, indexing guards and sitemap generation.- Arborist guest quote links go only through the arborist-link edge function and service-only link RPCs (hash-only tokens, per-request lock/expiry checks); never grant anon or authenticated access to link tables or RPCs, because the link token is the only guest credential.

- Platform record links use `?open=<id>&source=<platform|jobber>` (properties add `&property=`, crew uses `/platform/settings?crew=`), built by `src/lib/search/universalSearch.ts` and opened by `useRecordDeepLink`, so search, recent activity and shared URLs open the exact record independent of list filters. `useRecordDeepLink` opens only records verified by id + source + selected business (list rows can be another workspace's placeholder data), and search/recent activity offer only record types whose page `allowedSearchTypes` permits for the role, mirroring PlatformRoutes.

- Customer detail service counts come only from `src/lib/customers/customerDetail.ts` (recorded completions plus non-cancelled scheduled visits on business-local days before today, labelled "by schedule" and never written back as status; today/future stay upcoming) and `useCustomerProfile`, which reads Jobber jobs for Jobber clients plus only non-mirror native jobs of the source-linked platform customer, so history is never double-counted or joined by name/address.

- Analytics job value is schedule-based (`src/lib/analytics/serviceWork.ts`): past scheduled, non-cancelled work counts as done for reporting only, booked work stays separate, Jobber mirrors are deduped by source id; it never changes job status or triggers actions, because the owner doesn't mark jobs complete.
- Finance/Tax money totals come only from `src/lib/cashRecords.ts` via `useCashRecords` (cents, business-scoped, by cash date): successful payments/refunds, manual income, payroll, explicitly allocated shared expenses, and owner-sorted bank rows; unsorted, possible-duplicate or look-alike bank rows are held out, because the books must never double-count or guess splits. Bank CSVs import only through the owner-only `finance_import_bank_csv` RPC.
- All CSV exports go through `toCsv`/`csvCell`, which neutralises spreadsheet formulas.
- Climber-only accounts use a separate protected access mapping, never broad business membership; own draft/report/photo permissions and server-side API denial must stay aligned with the restricted page shell.
- Arborist pricing conversion uses cents and range midpoints; complete disposal totals replace tree charges, and office-opted alternatives use a required base plus mutually exclusive deltas so approval and downstream invoices never double-charge. Disposal grouping preserves required work descriptions in persisted customer scope; disabling is blocked while unrelated choice groups exist so work is never silently deleted.
- Website analytics: the public site records each call/text tap once through the delegated `handleTrackedClick` (placement from `data-track-placement`), never per-component handlers; `trackEvent` and the `track-event` function drop private routes, non-production hosts, query tokens and non-allowlisted properties. Owner-facing numbers come only from the owner-gated `website_analytics_summary` RPC (site hosts mapped per business inside it, legacy aliases normalised and de-duplicated), because raw rows double-count and mix app traffic.
- Quote AI ("Describe your quote") runs only in the `quote-ai` edge function (owner/office roles via `get_user_role`, climbers denied, bounded audio/text); the AI returns scope sections and quantity/unit/rate lines only — all money is recomputed in cents by `src/lib/quote-ai.ts`, unclear prices stay unresolved and block saving, and Apply never changes customer, tax, discount or deposit, because AI totals and guessed prices must never reach a customer.
- Quotes may be saved as unassigned drafts (customer_id null); the `guard_quote_customer_assignment` trigger allows choosing a same-workspace customer only once on an unsent draft and blocks sending without one; get-quote-public/approve-quote/create-checkout refuse quotes without a customer, so existing quote relationships are never rewritten and unassigned drafts stay office-only.
- Both workspaces share one platform theme (GCP's near-black + emerald tokens); PPS keeps only its own name, logo and records. Full-screen screens outside PlatformLayout (quote builder) must apply `workspaceThemeVars` themselves.
- Public quote deposits come only from the quote's own `deposit_required_flag` and saved deposit amount (`src/lib/quote-deposit.ts`, mirrored in create-checkout), the brand never implies a deposit; GCP public quotes stay approval-only (paid later by invoice) and only PPS may start deposit checkout; the public page never shows a payment as received, because customers must only be asked for the deposit the office actually set.
